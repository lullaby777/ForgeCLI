修复默认构造多个 Agent 时，任务清单和子 Agent 工具串扰的问题。

复现：不传 tools 创建 Agent A，写入 A 的待办，再创建 Agent B。
B 能看到 A 的待办；B 更新待办也会覆盖 A 的清单。
同时，创建 B 后，A 的 agent 工具可能关联 B，导致 A 派生子 Agent 时使用 B 的模型、权限和 hooks。

要求：
1. 每个默认 Agent 有独立且初始为空的任务清单，互相更新、清空不得串扰，注入提示词的清单也不能泄漏。
2. 创建其他默认 Agent 后，先前 Agent 的子 Agent 工具仍关联正确的父 Agent。
3. 派生子 Agent 使用所属父 Agent 的模型、权限、hooks 和上下文上限；清单独立为空，不能递归派生。
4. 保持默认工具名称、参数和能力兼容，保持消息历史隔离。
5. tools=[] 仍表示不提供工具。显式传入的自定义工具保留调用方提供的对象及资源，
   不能通过无条件深拷贝这些对象破坏兼容性；主动复用同一个有状态自定义工具的场景不在本题范围。
6. 本题聚焦 Agent 默认构造路径，不要求重构整个 CLI 或实现任意第三方工具克隆协议。
7. 新增离线开发测试，用假模型验证，不实际调用模型接口；不修改或删除已有测试。
8. 不读取或修改原项目 baseline 中的外部验收材料。不修复换行、会话容错、空回复等其他问题。
9. 已有 README 总行数检查失败不处理；如果本次源码改动使文档里的具体行数引用失效，可同步对应引用。
