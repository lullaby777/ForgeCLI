修复 edit_file 在小范围编辑时改变文件换行格式的问题。

复现：临时 UTF-8 文件原始字节为 b'alpha\r\nbeta\r\n'，
调用 edit_file 把 beta 替换成 BETA，结果变成 b'alpha\nBETA\n'。
预期为 b'alpha\r\nBETA\r\n'。

本题范围与要求：
1. 只考虑统一使用 CRLF 或 LF 的 UTF-8 文件；混合换行、纯 CR 换行不属于本题验收范围。
2. 单词替换不得改变未编辑部分的字节、空行和文件末尾的换行状态。
3. 在 CRLF 文件中，old_string 用普通 LF 表示多行文本时仍能匹配；
   old_string 使用 CRLF 时也能匹配。new_string 中的 LF/CRLF 换行按目标文件风格写入，不能产生双重 CR。
4. LF 文件的单行和多行替换保持正常。
5. 保持唯一匹配：找不到或多处匹配均拒绝写入，不新增撤销记录。
6. 非 UTF-8 文件仍应拒绝修改。成功编辑后差异输出只反映实际修改；
   undo 在模拟重启后也应逐字节恢复原文件。
7. 不得修改或删除已有测试；可新增开发测试，不读取或修改原项目 baseline 下的外部验收材料。
8. 保持工具接口。不要修复会话容错等其他问题，也不处理已有 README 行数检查失败。
   如果本次源码变化使文章里的具体行数失效，可同步更新对应引用，不修改测试来降低标准。

请阅读代码、修复并运行相关测试，最后说明改动、验证结果和未解决问题。
