# 从第四题 v4 阶段化组失败现场续跑

正式目录 `/tmp/corecoder-resume-01/task04-staged`。保留 v4 最后的补丁与会话消息，历史路径重定位到新副本，不重新执行历史工具调用。
这不是从原始 bug 起点重跑，也不是新的两组对照。只验证回归门禁对一个固定失败现场的恢复。
恢复的是消息历史及当前文件；不是任意内存状态的完整检查点。此现场没有需恢复的 todo/子任务状态。

关键：回归豁免来自修复前 original-source 的完整测试，不来自已失败的 v4 工作区。
本地起点应为原有 README 总行数失败；v4 剩余的具体文档引用失败必须识别为新增失败。
运行时在首次模型调用前重查目标验收与完整回归，把发现的新增失败反馈给模型。后续目标与回归都合格才 completed=true。

新副本运行时采用已实现回归门禁的主项目 repair.py/cli.py，其余运行时代码沿用 v4 冻结版本；候选工作区保持 v4 现场不变。
运行脚本有一处基线适配：覆盖控制器获取 baseline 的步骤，读取准备阶段从干净原始源码产生、并已封存的基线报告；其余续跑、失败反馈和停止决策沿用新控制器。
外部验收、回归命令、测试、配置、会话、基线报告、干净源码及运行时均封存核对。不会让模型更改已有测试或扩大失败豁免。

模型保持 deepseek-flash，温度 0、输出上限 8192、上下文配置 128000、请求超时 60 秒、SDK 自动重试关闭。
v4 已用 16 次入口调用，新阶段最多 14 次，合计不超过 30；每次最多 10 轮，新阶段最多 3 次尝试，连续两次无进展仍停止。
900 秒为新阶段总执行上限（含启动检查），目标及回归各次上限 60 秒，最终独立复核上限另为 60/120 秒。
新阶段尝试次数、耗时、token 与 v4 历史记录分开；这不是沿用 v4 剩余时间/尝试数的严格同预算实验。入口计数不是费用硬上限。

## 手动续跑

在终端设置好有效 CORECODER_API_KEY，不在聊天或截图中显示密钥。以下命令才会调用真实模型，准备阶段没有执行：

```sh
/tmp/corecoder-resume-01/venv/bin/python /tmp/corecoder-resume-01/runner/run.py --live
```

任意目录可启动，只运行一次，不额外人工提示、不先改文档、不直接进入旧副本或旧 CLI 续跑。
缺少密钥或 --live 不启动；已有 run 目录拒绝覆盖。执行工具自动授权沿用 v4，任务仅限新工作区，目录不是安全隔离边界。

结束后汇总（不调用模型）：

```sh
/tmp/corecoder-resume-01/venv/bin/python /tmp/corecoder-resume-01/runner/summary.py
```

重点看 functional_passed、completed、acceptance/regression、新增失败、停止原因和 total_calls_with_v4。
initial_feedback_usage 记录启动前发现的回归失败是否进入模型请求并收到响应；retry_feedback_usage 记录本轮后续反馈是否真的进入下一次尝试。
run/controller/result.json 保留两道检查、冻结起点、逐次反馈和停止原因；run/final 保存最终独立复核。run/change.patch 只表示相对 v4 现场的新增修改。

## 离线检查

准备阶段在原始源码上跑完整回归，再在失败现场跑目标验收和完整回归，确认目标 14/14 通过、具体文档引用仍为新增失败。
另将真实 v4 现场复制到临时目录，以固定响应验证：只说好了但没改文档会回归失败并无进展停止；收到反馈后用编辑工具同步文档可两关通过。
快速模拟只运行两个真实文档检查，正式起点核对及手动续跑使用完整回归；不能把模拟成功当作真实模型成功。正式候选文件不会预先修好。
