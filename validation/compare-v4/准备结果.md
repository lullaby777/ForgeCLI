## 手动运行

终端中需已有有效 CORECODER_API_KEY。依次执行，每组一次，不追加人工提示：

```sh
/tmp/corecoder-compare-04/venv/bin/python /tmp/corecoder-compare-04/runner/run.py task04 generic --live
/tmp/corecoder-compare-04/venv/bin/python /tmp/corecoder-compare-04/runner/run.py task04 staged --live
```

这两条才会调用真实模型；本次准备没有执行。

完成后汇总（不调用模型）：

```sh
/tmp/corecoder-compare-04/venv/bin/python /tmp/corecoder-compare-04/runner/summary.py
```

每组 run/feedback-usage.json 保存 generated、submitted、used、response 四个层次的统计，以及每份反馈对应的请求编号、下一次尝试调用数、修改事实和验收结果。used 仅指进入模型入口请求，不等于模型理解或采纳。硬超时导致结果缺失时应报告不完整，不能算作零使用。

每组 run/summary.json 保存最终评分、执行状态、token、耗时、新增回归失败和文件保护检查。run/controller/result.json 保存逐次尝试的完整事实。已有 run 拒绝覆盖，失败现场也保留。更多说明见 runner/README.md。

本轮的目标是观察反馈实际进入续跑后的效果；若首次便通过，或反馈没有真正进入请求，就如实报告，不据此推断反馈优劣。每组单次结果仍不能证明稳定成功率。
